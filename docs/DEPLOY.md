# Публикация сайта на Vercel

Инструкция для того, кто не программист. Всё делается мышью в браузере,
кроме одного шага с командами — их можно скопировать как есть.

Vercel сам понимает, что перед ним Next.js, и настраивать в нём ничего не
нужно.

**Про тариф.** Бесплатный тариф Hobby по правилам Vercel — только для
некоммерческих проектов. Лендинг, который сдаёт офис, под это описание не
подходит, поэтому формально нужен тариф Pro, около 20 долларов в месяц за
пользователя. Технически сайт заработает и на бесплатном, но это нарушение
условий, и аккаунт могут ограничить в самый неподходящий момент. Решать вам;
я обязан назвать это до публикации, а не после.

---

## Что нужно приготовить заранее

| Что | Где взять |
|---|---|
| Аккаунт на github.com | бесплатная регистрация |
| Аккаунт на vercel.com | войти через тот же GitHub — так проще |
| Токен Telegram-бота | у @BotFather, команда `/mybots` → бот → API Token |
| ID чата, куда идут заявки | лежит в файле `.env.local` на компьютере, строка `TELEGRAM_CHAT_ID` |
| Домен | если он уже куплен — доступ в панель регистратора |

Файл `.env.local` в репозиторий намеренно не попал: в нём секретные значения.
Их вводят в Vercel руками, один раз, — об этом шаг 3.

---

## Шаг 1. Выложить код на GitHub — уже сделано

Репозиторий создан и код в нём: **github.com/arcteryxmove/icity-office-244**,
приватный, ветка `main`. Начинайте сразу с шага 2, в списке репозиториев
Vercel выбирайте `icity-office-244`.

Дальше в этом разделе — на случай, если репозиторий придётся заводить заново.

1. Зайдите на github.com, нажмите **New repository**.
2. Имя — например `icity-landing`.
3. Выберите **Private**. Это важно: в репозитории лежат планировки и
   визуализации объекта, публичными им быть незачем.
4. **Не ставьте** галочки «Add a README», «Add .gitignore», «Choose a
   license» — репозиторий должен быть пустым, иначе следующий шаг упрётся
   в конфликт.
5. Нажмите **Create repository**. GitHub покажет адрес вида
   `https://github.com/ваш-аккаунт/icity-landing.git` — скопируйте его.
6. Откройте Терминал (Spotlight → «Терминал») и выполните три команды,
   подставив свой адрес во вторую:

```
cd ~/Projects/icity-landing
git remote add origin https://github.com/ваш-аккаунт/icity-landing.git
git push -u origin main
```

GitHub спросит логин и пароль — вместо пароля нужен Personal Access Token
(github.com → Settings → Developer settings → Personal access tokens). Проще
поставить приложение **GitHub Desktop**: там тот же шаг делается кнопкой
**Publish repository**, без токенов.

Готово, когда страница репозитория на github.com показывает файлы проекта.

---

## Шаг 2. Подключить проект к Vercel

1. vercel.com → **Add New…** → **Project**.
2. В списке **Import Git Repository** найдите `icity-landing` → **Import**.
3. Vercel сам определит: Framework Preset — **Next.js**. Ничего в полях
   Build Command, Output Directory и Install Command менять не нужно.
4. Пока **не нажимайте Deploy** — сначала переменные, следующий шаг. Они на
   этом же экране, раздел **Environment Variables**.

---

## Шаг 3. Три переменные окружения

Разверните **Environment Variables** и добавьте три строки. Слева имя,
справа значение.

| Имя | Значение | Зачем |
|---|---|---|
| `TELEGRAM_TOKEN` | токен бота от @BotFather | без него заявки не уходят |
| `TELEGRAM_CHAT_ID` | из `.env.local` | адрес чата, куда падают заявки |
| `NEXT_PUBLIC_SITE_URL` | `https://ваш-домен.ru` | адрес сайта в карточке ссылки, в sitemap и в канонических ссылках |

Про `NEXT_PUBLIC_SITE_URL`: пишется без косой черты на конце. Если домена
ещё нет, поставьте временный адрес, который выдаст Vercel
(`что-то.vercel.app`), а после привязки домена поправьте — как, написано в
шаге 5.

Галочки окружений: отметьте **Production** и **Preview**. Тогда форма
работает и на черновых сборках. Учтите, что заявка с черновика придёт в тот
же чат, что и настоящая.

---

## Шаг 4. Первый деплой

Нажмите **Deploy** и подождите одну–три минуты. Когда появится надпись
**Congratulations**, сайт уже открыт по адресу вида
`icity-landing.vercel.app`. Откройте его и убедитесь, что страница
загружается.

---

## Шаг 5. Свой домен

1. В проекте: **Settings** → **Domains** → введите домен → **Add**.
2. Vercel покажет на экране, какие записи добавить у регистратора домена:
   обычно запись **A** для голого домена и **CNAME** для `www`.
   **Берите значения с экрана Vercel, а не из инструкций в интернете** —
   они меняются, и старые адреса ведут в никуда.
3. Обновление записей занимает от нескольких минут до нескольких часов.
   Vercel сам поставит сертификат, когда домен заработает.

**Обязательный шаг после привязки домена.** Адрес сайта вшивается в
страницы во время сборки, а не подставляется на лету. Поэтому:

1. **Settings** → **Environment Variables** → откройте `NEXT_PUBLIC_SITE_URL`
   → впишите новый адрес → **Save**.
2. **Deployments** → у верхней строки кнопка **⋯** → **Redeploy** →
   подтвердите.

Без этой пересборки в карточке ссылки и в `sitemap.xml` останется старый
адрес. Сайт при этом будет работать, поэтому ошибку легко не заметить —
проверка ниже её ловит.

---

## Проверка после деплоя

Пройдите список сверху вниз. Слева — что сделать, справа — что должно быть.

| № | Что сделать | Что должно быть |
|---|---|---|
| 1 | Открыть `https://ваш-домен.ru` | перебрасывает на `/ru`, страница по-русски |
| 2 | Нажать **EN** в шапке | тот же экран по-английски, адрес `/en` |
| 3 | Открыть сайт с телефона по мобильной сети | цена **1 300 000 ₽ / мес** видна сразу, ещё до того как подгрузятся фотографии |
| 4 | Заполнить форму внизу и отправить | на экране «Заявка отправлена», в Telegram приходит сообщение с именем, контактом и временем по Москве. **Тестовое сообщение потом удалите** |
| 5 | Отправить ссылку на сайт самому себе в Telegram или WhatsApp | разворачивается карточка: голубой фон, «244,1 м²», ставка, строка «БЦ iCITY · Space Tower · 23 этаж» |
| 6 | Посмотреть на вкладку браузера | синий квадратик с белой буквой **i** |
| 7 | Открыть `https://ваш-домен.ru/robots.txt` | текст из трёх строк, в последней — **ваш домен**, а не `localhost` |
| 8 | Открыть `https://ваш-домен.ru/sitemap.xml` | два адреса, `/ru` и `/en`, оба на **вашем домене** |
| 9 | На телефоне прокрутить страницу вниз | после первого экрана снизу появляется полоса «Позвонить · Записаться», обе кнопки работают |
| 10 | На телефоне протянуть план пальцем вбок | план листается, справа у него растушёванный край-подсказка |

Пункты 7 и 8 — это и есть проверка, что шаг 5 доведён до конца. Если там
`localhost` — вы не пересобрали сайт после смены домена.

Если карточка ссылки в пункте 5 показывает старую картинку или не
показывает ничего: Telegram кэширует превью. Отправьте ссылку боту
**@WebpageBot** и нажмите там «Update preview» — кэш сбросится.

## Если что-то пошло не так

**Форма пишет «Не удалось отправить».** Vercel → **Deployments** → верхняя
строка → вкладка **Runtime Logs**. Ищите строки, начинающиеся с `lead:`.

- `lead: TELEGRAM_TOKEN или TELEGRAM_CHAT_ID не заданы` — переменные из шага 3
  не добавлены или добавлены не в то окружение. Добавьте и нажмите Redeploy:
  переменные подхватываются только при новой сборке.
- `lead: Telegram ответил 403` — бот не может писать в чат: его выгнали из
  группы или он не начинал переписку с получателем.
- `lead: Telegram ответил 400` — неверный `TELEGRAM_CHAT_ID`.

**Сайт открывается, но выглядит сломанным.** Скорее всего показана старая
сборка из кэша браузера. Обновите страницу с очисткой кэша: Cmd+Shift+R.

**Деплой упал.** Vercel → Deployments → красная строка → **Building** — там
текст ошибки. Самая частая причина — код, который не собрался; предыдущая
рабочая версия при этом остаётся в проде, сайт не падает.

**Нужно откатиться на вчерашнюю версию.** Deployments → найдите нужную
строку → **⋯** → **Promote to Production**. Возврат занимает секунды.

## Как обновлять сайт дальше

Любая правка в коде: `git push` — и Vercel пересоберёт сайт сам, за пару
минут, без единого нажатия.

**Если поменяется ставка или площадь.** Числа лежат в двух местах, и оба
надо обновить:

1. Тексты — `src/i18n/messages/ru.json` и `en.json`.
2. Картинка для карточки ссылки — она статическая, тексты в неё вшиты при
   сборке. Пересобрать командой `npm run og` (нужен установленный
   playwright, команда установки напечатается сама, если его нет).

Если пересобрать только тексты, на сайте будет новая цена, а в карточке
ссылки в мессенджере — старая. Это тот случай, когда ошибку не видно
изнутри сайта.
